## 排查原则：一次只改一个变量

AI 绘图的问题很少是「某一个参数错了」，多数是几个变量叠在一起。
所以排查的第一步不是翻论坛，而是**回到最后一次能出图的配置**，然后一次只改一处。

## 症状一：显存不足（Out of Memory）

```text
torch.cuda.OutOfMemoryError: CUDA out of memory.
```

按这个顺序处理，命中率从高到低：

1. **降分辨率**。1024×1024 换成 768×768，显存占用大约降到一半多一点。出图后再用放大流程补分辨率。
2. **换量化权重**。FP16 换 FP8，然后才是 GGUF Q8 / Q5。量化会牺牲一点细节，但比跑不起来强。
3. **减少同时驻留的模型**。LoRA 叠了三四个、ControlNet 也开着，显存自然不够。
4. **清缓存**。ComfyUI 顶部的 `Free model and node cache` 按钮能立刻释放上一轮占用的显存。
5. **检查系统内存**。显存不足时驱动会把数据挪到内存，内存也满了就会直接崩，而不是报 OOM。

## 症状二：出图纯黑、纯噪点或纯灰

| 表现 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 全黑 | VAE 不匹配或 VAE 未接 | 换通用 VAE，确认 VAE Decode 有连线 |
| 全噪点 | 步数太低、采样器不匹配 | 步数提到 20+，采样器换 `euler` 试 |
| 全灰 | CFG 过低 | 把 guidance / CFG 提到 3.5 左右 |
| 一半正常一半崩 | 分辨率不是 64 的倍数 | 宽高改成 64 的整数倍 |

## 症状三：模型加载失败

```text
Error while deserializing header / unexpected key(s) in state_dict
```

- **文件名带 `(1)` 或中文括号**：有时会导致路径解析问题，改名为纯英文。
- **下载不完整**：对比文件大小与官方仓库，safetensors 拿到一半就中断是很常见的情况。
- **模型类型放错目录**：UNet-only 的权重丢进 `checkpoints` 会报缺 CLIP。
- **节点版本与模型不匹配**：老节点读不了新结构，先更新节点包再试。

## 症状四：节点突然全红

更新插件后最常见。处理顺序：

1. 先看控制台报错的第一行，通常明确写了缺哪个模块。
2. 缺依赖就在对应插件目录里补装（注意用 ComfyUI 自带的 Python 环境）。
3. 还是红就回滚插件版本——能跑通比最新更重要。

## 症状五：速度突然变慢好几倍

- 检查是不是悄悄跑在 CPU 上（日志里会写 `Using cpu`）。
- 检查是不是模型被换成了更大的量化前版本。
- 检查系统盘是不是快满了：临时文件写不进去时，速度会断崖式下降。

## 一个能省很多时间的习惯

每次跑通一套配置后，把**模型文件名、节点包版本、显存占用、耗时**记在作品条目里。
下次出问题，先对照这份记录，能立刻判断是环境变了还是参数变了。
